# Перенос UI и подключение backend

## Границы модулей

Все общие модули компилируются в Java 8. `agent-api` содержит неизменяемые
значения, `AgentBackend`, `Form` и `Value`; он не знает Codex, Minecraft или JSON.
`agent-codex` зависит от API и содержит локальный процесс, JSON-RPC, декодирование
версии 0.163.0, именованный каталог действий и преобразование форм.
`core` зависит только от API: владеет рабочей областью, диалогами, очередями,
историей и сохранением локального состояния. `chat-ui` зависит от API/core и
рисует через `Surface`. `forge-1.7.10` связывает эти модули с игровым клиентом.
`verifyArchitecture` проверяет граф и запрещённые зависимости исходников.

## Новый backend

1. Реализуйте `AgentBackend` с постоянным уникальным `id()`; передайте экземпляр
   в коллекцию конструктора `WorkspaceController`. Команда `/backend` предложит его автоматически.
2. Все вызовы и завершения futures принадлежат одному потоку владельца.
   Фоновые IO-потоки складывают результаты в очередь; `pump(budget)` доставляет
   не больше указанного количества событий/ответов. Не вызывайте UI из IO-потока.
3. `connect` канонизирует workspace и выдаёт новую generation. Каждый ThreadKey
   включает connection, а каждый RequestKey — thread и непрозрачный token.
   Проверяйте старые handles; `close` завершает ожидающие futures ошибкой,
   инвалидирует запросы и останавливает принадлежащие реализации ресурсы.
4. Отдавайте capabilities с причинами недоступности, полный пагинированный каталог
   моделей и настройки, которыми действительно располагает backend. Не подменяйте
   отклонённую модель. Количество параллельных задач задаёт `concurrentTurns`.
5. Каталог диалогов и история используют непрозрачные cursors. История возвращает
   элементы от новых к старым. События используют устойчивые item id: финальный
   snapshot заменяет deltas, повторная история не создаёт дубль. Сначала завершайте
   обновление внутреннего состояния операции, затем её возвращаемый future.
6. Дополнительные операции описываются `Action` + `Form`, результат — `ActionResult`.
   Созданный диалог, изменение следующих настроек и удаление передавайте typed
   effects, чтобы core применил их без знания RPC. Не добавляйте поля raw RPC в UI.
7. Выполните `BackendScenarios` на реализации/изолированном транспорте. FakeBackend
   в testFixtures задаёт минимальную альтернативу; ChatPanelTest проверяет замену
   backend без изменения панели. Не выдавайте fake-проверку за живую совместимость.

Поддерживаемые поля: text/secret, number/integer, boolean, choice/multichoice,
resource и group. Валидация выполняется до отправки и повторно на backend.
Неизвестный обязательный запрос должен получить явную ошибку, а не подтверждение.
Обычные неизвестные уведомления можно показать предупреждением. Hidden reasoning
не переносится в UI: только опубликованные summary/status.

## Адаптер другой версии Minecraft

1. Создайте отдельный модуль для соответствующего API; общий UI менять не нужно.
2. Реализуйте `Surface`: метрики и рисование текста, прямоугольники, вложенный
   clipping, clipboard, подтверждённое открытие ресурсов, закрытие панели и переход
   к игровому вводу. Координаты логические; преобразуйте scale и scissor один раз
   на границе. Сохраняйте состояние графического контекста после рисования.
3. Встройте панель в обычный chat host. Разделяйте обработчики игрового ввода и
   агентского composer: агентский текст никогда не передавайте chat/network API.
   Сохраняйте начальный `/`, игровой черновик и настройки прозрачности/масштаба.
4. На client tick вызывайте `controller.tick(budget)`, даже когда чат закрыт.
   Закрытие панели вызывает `panel.closed()`, но не останавливает задачи.
5. Получайте корень реального локального сейва, а не название мира/измерение.
   `WorldWorkspace.open(root)` создаёт `codex-workspace`. При смене экземпляра
   сервера/мира закройте старый controller, затем создайте новый. Для удалённого
   сервера без доступа к сейву показывайте причину недоступности.
6. Свяжите мышь, колесо, Enter/Shift+Enter, Tab/Shift+Tab, Escape, PageUp/PageDown,
   клавиши редактирования и clipboard с ChatPanel. Проверьте узкий viewport,
   масштабирование и независимость игрового/агентского ввода.

SoundLoadingTransformer относится только к 1.7.10. Его нельзя автоматически
переносить в другие версии: он сериализует завершение загрузчика OpenAL при reload.
Наличие общего ядра не подтверждает runtime-совместимость нового адаптера или
других модов, заменяющих чат/аудиоклассы.

## Состояние и восстановление

История принадлежит backend. Локальный UI хранится в `.harness-ui-v1` внутри
workspace; имена файлов вычисляются из backend/thread, поэтому одинаковые id
разных backend не конфликтуют. Сохраняются черновик, cursor, scroll anchor,
expanded, следующие настройки и вложения. При восстановлении задачи не
отправляются повторно. Оборванные запросы помечаются disconnected; соединение
и диалог нужно открыть снова. Все диалоги одного мира разделяют файловую область;
это не отдельные worktrees. `/cd` и `/worktree` — согласованное исключение.

## Проверки и воспроизведение

`gradlew test :forge-1.7.10:build` выполняет изолированные проверки, проверку
архитектуры и reobfuscation. Запуск игры в эту команду не входит.
`scripts/capture-codex-fixtures.py` проверяет закреплённую версию, генерирует схемы
и сохраняет synthetic fixtures; `--verify` проверяет уже сохранённые примеры.
Действия сверяются с `action-request-schemas.json` в ActionProtocolTest.
Матрица пользовательских команд: [codex-coverage.md](codex-coverage.md).

Измерения RecordingSurface от 2026-10-19: 100 диалогов / 10 000 элементов,
100 кадров при ширине 240 — 0.6094 мс суммарно; последний кадр рисовал 1 карточку
и измерял 11 символов. Поток текста 340 тысяч символов, 100 append/render кадров —
44.076 мс суммарно. Это headless CPU-измерения на текущей машине, не FPS игры.
Тесты проверяют предел числа видимых карточек и не более 512 измеренных символов
из длинного сообщения за кадр. Детали читаются постранично без потери текста;
копирование возвращает полный текст. Нагрузка, metрики шрифта и GPU реального
адаптера требуют отдельной проверки при переносе.
