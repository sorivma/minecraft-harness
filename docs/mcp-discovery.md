# MCP discovery v1 (Forge 1.7.10)

Контракт связывает владельцев MCP endpoint с любым клиентом через стандартный
Forge IMC. Он содержит только данные: общая Java-библиотека, зависимость от
Harness и чтение чужих `.cfg` не нужны. Моды без этого контракта не объявляют
endpoint автоматически; сканирования портов и запуска внешних процессов нет.
Версия находится в ключах сообщений. В v1 поддержан Streamable HTTP.

## Жизненный цикл

1. Клиент во время `FMLInitializationEvent` перебирает
   `Loader.instance().getActiveModList()` и отправляет каждому моду
   `FMLInterModComms.sendMessage(modid, "agent-mcp:discover/v1", "")`.
2. Владелец endpoint принимает строковые запросы в `FMLInterModComms.IMCEvent`
   и запоминает `message.getSender()`. В Forge 1.7.10 это событие приходит
   **до post-init**, поэтому готовность сервера на этом этапе не предполагается.
3. После успешного запуска endpoint, не позднее конца своего
   `FMLPostInitializationEvent`, владелец отвечает каждому клиенту через
   `FMLInterModComms.sendRuntimeMessage(this, sender, "agent-mcp:server/v1", json)`.
   `this` должен быть зарегистрированным экземпляром `@Mod`.
4. Клиент собирает ответы через `fetchRuntimeMessages(this)` в
   `FMLLoadCompleteEvent`, когда post-init всех модов уже завершён.

Один ответ объявляет один сервер. Мод может отправить несколько ответов с разными
`id`. Объявляются только запущенные endpoint, с фактическими URL и credentials.
Изменение конфигурации endpoint требует перезапуска игры.

## Данные ответа

Строковый payload — JSON-объект:

```json
{
  "id": "minecraft",
  "transport": "streamable-http",
  "url": "http://127.0.0.1:25581/mcp",
  "http_headers": { "Authorization": "Bearer <private HTTP token>" },
  "startup_timeout_sec": 20,
  "tool_timeout_sec": 30
}
```

`id`, `transport` и `url` обязательны и имеют строковый тип. Локальный `id`
состоит из ASCII-букв, цифр и дефисов, уникален в пределах мода. `url` — абсолютный
HTTP(S) URL без user info и fragment. `http_headers` необязателен: объект
строковых HTTP-заголовков без CR/LF в значениях. Таймауты — необязательные
положительные целые секунды, по умолчанию 20 и 30. Неизвестные поля игнорируются.

Harness формирует имя Codex-сервера `harness_<sender-modid>__<id>`; modid в этом
адаптере должен состоять из ASCII-букв, цифр, дефисов и подчёркиваний. Повторное
объявление одного имени и некорректный ответ показывают ошибку конфигурации
рабочей области. Payload и токены не включаются в сообщения об ошибках.

## Настройки мира

При каждом открытии мира Harness пересобирает свой блок в
`codex-workspace/.codex/config.toml`. Отсутствующий мод удаляется из блока,
изменённые URL и credentials заменяются. Запись атомарна, когда это поддерживает
файловая система; одинаковое содержимое повторно не записывается. При отсутствии
MCP-модов создаётся пустой управляемый блок. Пользовательские настройки вне блока
сохраняются; имена `harness_...` и строки маркеров зарезервированы для генератора.
Повреждённые или повторные маркеры дают ошибку без перезаписи файла.

JSON не содержит TOML, команд shell или разрешений Codex. Генератор сам
экранирует строки и выбирает формат конкретного backend. Пользовательские
серверы, включая старые ручные подключения того же endpoint, сохраняются.
Лишнее ручное подключение можно удалить из настроек своего мира или Codex.

Протокол не предполагает отдельный MCP-сервер для каждого инструмента.
`minecraft-agent-tools` объявляет один host со всеми фактически установленными
провайдерами из `plugins/*.jar`; список инструментов Codex получает обычным MCP
discovery у самого сервера.
