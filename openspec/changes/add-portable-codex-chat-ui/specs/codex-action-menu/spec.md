## Purpose

Сделать возможности поддерживаемого Codex доступными через понятное меню в игре, включая модели и настройки, с проверяемым охватом команд.

## ADDED Requirements

### Requirement: Auditable command coverage
Релиз SHALL содержать матрицу всех команд проверенной версии Codex CLI с UI-входом, способом реализации и проверкой. Все реализуемые на целевой платформе через поддерживаемый протокол или локальное UI-действие команды MUST работать. Ограничения протокола/платформы SHALL быть явно перечислены с причиной и внешним способом выполнения, где он существует; незавершённая реализация MUST NOT считаться ограничением.

Согласованное продуктовое исключение: `/cd`, `/worktree` и эквивалентные способы смены workspace SHALL показывать объяснение привязки к миру и внешний путь через CLI; создание/смена рабочих областей вне мира не требуется.

#### Scenario: Coverage audit
- **WHEN** сравнивается каталог команд проверенной версии и матрица реализации
- **THEN** каждая команда учтена, доступные команды имеют работающий UI-путь, а исключения имеют подтверждённую причину

### Requirement: Searchable action menu
UI SHALL использовать slash-команды как основной путь управления. Ввод `/` SHALL показывать фильтруемые подсказки с описаниями; стрелки выбирают, Tab дополняет, Enter исполняет. Постоянная панель кнопок New/Model/Actions/Send/Stop/Connect MUST отсутствовать. Неизвестная slash-команда MUST оставаться в composer с ошибкой и MUST NOT отправляться модели. Карточки, формы, оформление и игровой chat host сохраняются.

#### Scenario: Find an action without knowing its command
- **WHEN** пользователь ищет действие по названию или назначению
- **THEN** меню показывает соответствующие действия и позволяет выполнить доступное действие без ввода команды

### Requirement: Dynamic model and parameter selection
UI SHALL получать модели и допустимые параметры от backend, показывать текущие модель, effort и tier при поддержке и применять выбор в соответствующем диалоге. Изменение во время задачи SHALL относиться к следующему сообщению и явно обозначаться.

#### Scenario: Model rejected by backend
- **WHEN** backend отклоняет выбранную модель или параметр
- **THEN** UI показывает ошибку, сохраняет сообщение и не подменяет модель молча

#### Scenario: Change settings while running
- **WHEN** пользователь выбирает другую модель во время выполнения
- **THEN** текущая задача сохраняет исходные параметры, а UI показывает настройку следующего сообщения

### Requirement: Operational panels
UI SHALL предоставлять панели диалогов, режима работы, разрешений, контекста/вложений, review/diff, skills/MCP, аккаунта/лимитов, настроек и справки в пределах доступности backend. Действия, требующие внешнего приложения, SHALL объяснять переход до его выполнения. Изменение разрешений MUST соблюдать ограничения backend.

#### Scenario: Policy forbids permission change
- **WHEN** пользователь открывает настройку разрешений, запрещённую политикой backend
- **THEN** UI показывает причину недоступности и не пытается обойти политику

#### Scenario: Runtime capability disappears
- **WHEN** после переподключения функция не поддерживается текущим backend
- **THEN** каталог обновляется и показывает объяснение вместо работающей на вид кнопки


#### Scenario: Execute commands from composer
- **WHEN** пользователь вводит `/clear`, `/model` или `/mcp` и нажимает Enter
- **THEN** выполняется локальное действие либо открывается соответствующий выбор/операция backend без отправки slash-текста модели

#### Scenario: Complete or cancel a command
- **WHEN** пользователь выбирает подсказку стрелками и нажимает Tab либо Escape
- **THEN** Tab дополняет команду, а Escape скрывает подсказки с сохранением текста
