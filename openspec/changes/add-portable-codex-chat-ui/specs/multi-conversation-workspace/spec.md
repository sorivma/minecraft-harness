## Purpose

Позволить вести множество независимых диалогов агента в рабочей области мира, сохраняя историю, состояние и управление фоновыми задачами.

## ADDED Requirements

### Requirement: Conversation catalog
Система SHALL предоставлять список с поиском, созданием, открытием, переименованием, архивированием и восстановлением диалогов при поддержке backend. Каталог SHALL подгружаться страницами без фиксированного лимита числа доступных диалогов.

#### Scenario: Open an older conversation
- **WHEN** пользователь находит диалог за пределами первой страницы и открывает его
- **THEN** восстанавливается его история, включая пользовательские сообщения, ответы и доступные действия агента, без примеси другого диалога

### Requirement: Independent concurrent conversations
Каждый диалог SHALL иметь собственные настройки, историю, состояние задачи, черновик и запросы. Поддерживающий параллелизм backend SHALL позволять одновременно работать разным диалогам; остальные SHALL показывать очередь. Переключение UI MUST NOT останавливать работу.

#### Scenario: Interleaved activity
- **WHEN** два диалога одновременно получают текст, результаты инструментов и запросы решений
- **THEN** каждое событие попадает только в соответствующий диалог, а список показывает фоновые статусы и непрочитанные события

#### Scenario: Additional message while busy
- **WHEN** пользователь отправляет сообщение в работающий диалог
- **THEN** UI явно показывает отправку как уточнение при поддержке backend либо постановку в очередь, не теряет текст и позволяет отменить ожидающее сообщение

### Requirement: Workspace lifecycle
Диалоги SHALL быть привязаны к канонической рабочей области мира и backend. При закрытии мира система SHALL завершать его подключение, сохранять локальные черновики и исключать перенос задач/событий в другой мир. История backend SHALL сохраняться для дальнейшего продолжения.

#### Scenario: Change worlds
- **WHEN** пользователь закрывает мир A и открывает мир B
- **THEN** события и запросы мира A не отображаются в B, а после возврата в A доступны его сохранённые диалоги

### Requirement: Explicit recovery
После сбоя подключения система SHALL показывать прерванное состояние и возможность восстановить диалог без автоматического повторного запуска пользовательского запроса.

#### Scenario: Connection lost during tool execution
- **WHEN** процесс backend завершается во время задачи
- **THEN** UI не сообщает об успешном завершении, деактивирует старые решения и после восстановления согласует историю с backend без повторного выполнения задачи
