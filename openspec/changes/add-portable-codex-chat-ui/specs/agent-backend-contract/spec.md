## Purpose

Отделить интерфейс и управление диалогами от конкретного агентного backend, чтобы его можно было заменить без изменения UI и Minecraft-адаптеров.

## ADDED Requirements

### Requirement: Independent backend contract
Система SHALL предоставлять отдельный версионируемый контракт диалогов, моделей, действий, событий, интерактивных запросов и ошибок без типов Minecraft, графической библиотеки и протокола конкретного провайдера. Backend MUST работать без загруженного UI.

#### Scenario: Replace backend implementation
- **WHEN** вместо Codex подключён независимый тестовый backend, реализующий контракт
- **THEN** существующий UI позволяет создать диалог, отправить сообщение, показать действие инструмента и ответить на запрос без изменений кода UI

#### Scenario: Headless operation
- **WHEN** backend выполняет задачу при закрытом UI
- **THEN** события обрабатываются и доступны при следующем открытии интерфейса

### Requirement: Capability driven actions
Backend SHALL объявлять поддерживаемые операции, модели, ограничения и типизированные параметры расширений. UI MUST отображать доступность через контракт, без знания wire-методов провайдера.

#### Scenario: Backend lacks a capability
- **WHEN** backend не поддерживает выбор reasoning effort или параллельные задачи
- **THEN** UI показывает соответствующее ограничение и не отправляет неподдерживаемую операцию

### Requirement: Conversation ownership and connection lifecycle
Идентичность диалога SHALL включать backend и workspace. Смена модели SHALL отличаться от смены backend. Смена backend MUST NOT переносить контекст существующего диалога или незаметно отменять его задачу. Отключение SHALL завершать ожидающие операции явным состоянием ошибки.

#### Scenario: Select another backend
- **WHEN** пользователь выбирает другой backend для нового диалога
- **THEN** новый диалог создаётся там, а прежние диалоги сохраняют исходного владельца и историю

#### Scenario: Late event after reconnect
- **WHEN** приходит событие от старого поколения подключения
- **THEN** оно не изменяет состояние нового подключения и не активирует старые подтверждения
